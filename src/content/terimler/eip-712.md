## Nedir?

EIP-712, imzalanacak verinin yapılandırılmış biçimde tanımlanmasını sağlayan bir standarttır. Var oluş sebebi doğrudan [[blind-signing|kör imzalamayı]] azaltmaktır: veri bu standarda göre hazırlandığında cüzdan, kullanıcıya anlamsız bir özet yerine "kime", "ne kadar", "hangi tarihe kadar" gibi alan adlarıyla okunabilir bir ekran gösterebilir.

Standardın ikinci işi imzayı bir bağlama çivilemektir. İmza; uygulamanın adı, sürümü, çalıştığı ağ ve onu doğrulayacak sözleşmenin adresinden oluşan bir alan (domain) bilgisine bağlanır.

## Nasıl çalışır?

Uygulama önce veri tipini tanımlar: hangi alanlar, hangi türde. Sonra bu tip tanımı ile değerler, standardın tarif ettiği sırayla özetlenir; alan bilgisinin özeti de buna eklenir ve ortaya imzalanacak tek bir özet çıkar.

Sözleşme tarafında aynı hesap yeniden yapılır ve imzadan [[signature-verification-ecrecover|ecrecover]] ile adres geri çıkarılır. Çıkan adres beklenen adresse imza geçerlidir. Alan bilgisi hesabın içinde olduğu için, bir sözleşme için üretilmiş imza başka bir sözleşmede ya da başka bir ağda tutmaz.

## Örnek

```js
const domain = { name: "MyToken", version: "1", chainId: 1, verifyingContract: tokenAdresi };
const types = {
  Permit: [
    { name: "owner", type: "address" },
    { name: "spender", type: "address" },
    { name: "value", type: "uint256" },
    { name: "nonce", type: "uint256" },
    { name: "deadline", type: "uint256" },
  ],
};
const mesaj = { owner: sahip, spender: harcayan, value: 1000n, nonce: 0n, deadline: sonTarih };
const imza = await signer.signTypedData(domain, types, mesaj); // ethers v6
```

## Dikkat

Okunabilir olmak zararsız olmak değildir. Düzgün biçimlendirilmiş bir EIP-712 mesajı da birine varlıklarını harcama yetkisi verebilir; standart bunu görünür kılar, engellemez.

O yüzden ekrandaki `spender` ve `value` alanlarına, verdiğin bir [[allowance|harcama iznine]] bakar gibi bakmak gerekir. Bir de son geçerlilik alanı: uzak bir tarih, imzanın aylarca kullanılabilir kalması demektir.
